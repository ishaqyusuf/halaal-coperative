# ADR — Configure the mobile public legal origin per release target

Status: Accepted in source on 25 September 2026; public publication remains gated.

Preview validation clarification (29 September): an ordinary Preview build may omit `EXPO_PUBLIC_LEGAL_ORIGIN` while draft pages are under review, leaving signed-out external links explicitly unavailable. If Preview supplies the value, config evaluation now applies the same non-local, public HTTPS root-origin syntax checks as store builds; a malformed Preview value fails instead of silently disabling the links after installation. A source-level parity test checks that the six native external page targets match the six-page public preflight. This does not require effective publication in Preview or open protected draft pages to the public.

The signed-out mobile app previously opened hardcoded `halaalvest.com` Terms, Privacy, deletion and support URLs. The validation APK reached the deletion URL, but the Production page returned 404. A protected draft Preview cannot be treated as a public store policy URL.

Mobile external legal/support links now use `EXPO_PUBLIC_LEGAL_ORIGIN`. If it is absent or malformed, the app displays an unavailable notice and disables only external legal/support actions; signed-in document acknowledgement and account-privacy routes remain available. Store-QA and Production EAS profiles require a non-local HTTPS origin with no path, query, fragment or credentials; `.invalid` and `.test` hosts are rejected. The scoped store-QA runner requires this setting in the Preview-specific env file, not a shared shell or base dotenv value. The native-validation profile may omit it while testing unreachable API/dashboard endpoints.

The release validator and native link parser also reject reserved `.example` and documentation `example.com/.net/.org` hosts (including subdomains), matching the deletion-email origin guard. The native parser rejects local aliases and literal IPs as well. These syntax checks prevent a distributable build from treating documentation addresses as live policy pages; they do not establish that an accepted origin serves effective pages.

This is a configuration and failure-mode guard, not proof that the pages are live, public, approved or correct. Before either store submission, verify each effective Terms, Privacy, deletion, support and cooperative-disclosure route from an unauthenticated device using the exact origin embedded in the signed build. Approved publication and monitored deletion/support workflows remain separate gates.

Production EAS submission now runs the read-only `scripts/public-pages-preflight.ts` against the configured origin before EAS authentication. It requires all six policy/support paths to return public HTML without `noindex`, the deletion request form to render, the no-token `/delete-account/verify` route to return its recognizable incomplete-link page with `noindex`, and `/api/legal` to expose exact-origin effective Terms and Privacy acceptance documents. A missing or indexable verification route blocks submission because emailed links depend on it and can contain a private challenge identifier. A failed network check blocks submission. This is a source-level release guard, not delivered-email, token redemption, monitored-contact, retention, processor or signed-device proof. Internal/store-QA submission remains available for controlled testing without treating draft pages as public launch evidence.
The check reads the current submission environment; it cannot prove that an older selected EAS build embedded that same origin. Review the exact signed build's embedded configuration and device navigation before submitting its build ID.

The deletion verification check also requires `Cache-Control` to include `no-store` and `Referrer-Policy` to be `no-referrer`. The marketing Next configuration already sets both headers plus `X-Robots-Tag: noindex, nofollow` on this route. Requiring them from the served response catches a deployment that drops its private-link headers. The no-token probe cannot prove a delivered tokenized link or a later browser request.
