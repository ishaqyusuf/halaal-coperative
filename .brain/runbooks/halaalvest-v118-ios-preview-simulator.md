## Simulator startup and signing limit

The first disposable CocoaPods-cache Hermes binary crashed during JavaScript startup on isolated iOS 17.5 and 26.5 QA simulators (`EXC_BAD_ACCESS` in `HermesRuntimeImpl::debugJavaScript`). Its binary hash differed from the official React Native 0.81.5 iOS Release Hermes artifact. Replacing only the generated pod with that exact official public artifact (archive SHA-256 `4300c010d756c1d939e8bd8402fc28b70cad070c744ca2ed9059961fe067b512`, packaged simulator Hermes SHA-256 `3b56fdbd5ad62d1b75f039f8ae357052fd6e2a61da574e334d5cbdbeb4ca40ec`) and rebuilding removed the native crash. The JS bundle hash did not change. This isolates the crash to the disposable cached binary; it does not establish a repository source defect.

The rebuilt app then launched and remained open long enough to render [its own error screen](/private/tmp/halaalvest-v118-ios-preview-official-hermes-startup.png) (screenshot SHA-256 `a7ea4d41ccf83d929b44bc24157d6ff5151dfcb9ecd4dd25d192b2a7c4e95151`). It did **not** reach a healthy signed-in or signed-out screen: Expo SecureStore failed a synchronous Keychain read because the unsigned simulator process lacked `application-identifier` and `keychain-access-groups` entitlements (`securityd` error `-34018`). Two disposable ad hoc re-sign attempts verified on disk but iOS simulator refused to spawn the resulting apps (process spawn code 163). The unsigned Xcode output shows `Signature=adhoc`, `TeamIdentifier=not set` and `Sealed Resources=none`; neither it nor these probes represent a signed iPhone, TestFlight, App Store, or StoreKit purchase test. Do not mark startup or signed-device QA complete from this result.

Only dedicated QA simulators `AEC523FB-DAB8-46FD-852B-B17C65385F06` (iOS 17.5) and `85C301BB-C725-429F-A4EA-E13914FA8DB0` (iOS 26.5) were used. The pre-existing booted iPhone 17 Pro `9209F941-FEAD-44FE-A513-A86C21405DC2`, used by other work, was untouched. The dedicated devices were shut down/deleted after recording evidence.

## Remaining gate

A properly signed Preview build and isolated device/simulator run must verify real Keychain startup, privacy manifest in the accepted artifact, paywall/Restore and both member/staff entry paths. An Apple development simulator signature can prove local startup, but it cannot substitute for TestFlight/device distribution signing or a signed purchase. Keep the owner cloud hold in force; no source change was justified by this disposable check.
