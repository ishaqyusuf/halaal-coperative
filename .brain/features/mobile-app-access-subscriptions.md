# Personal mobile app access subscriptions

**Current pricing decision — 7 October 2026:** US$0.99 for six months and US$1.99 for one year are the owner-approved USD base prices, replacing the ₦500/₦1,000 Nigerian targets. Apple saved both United States-anchored schedules with recalculation across 175 territories; saved Nigeria prices are ₦1,500 and ₦3,200. Both subscriptions have all 175 current territories selected, with automatic future-territory inclusion off. Checkout must use store-returned localized prices. Google configuration and signed-device checkout remain unverified here. Older dated observations below are historical and do not override this decision. See [pricing ADR](../decisions/ADR-20261007-usd-personal-mobile-access-prices.md).

Apple publisher identity gate (29 September): Apple purchase verification now requires the centrally approved personal-team iOS bundle and an `APPLE_APP_ID` matching that record; while the record is pending, Apple catalog/verification cannot grant access. Google verification, Android package, personal subscription price/duration policy, web access and role permissions are unchanged. Signed personal-team products and purchase/Restore QA remain open under the owner cloud hold. See [ADR](../decisions/ADR-20260929-personal-apple-publisher-handoff.md).

Apple Organization identity correction (29 September): purchase verification now binds to the centrally approved Zeroes Organization HalaalVest bundle `com.halaalvest.mobile` and requires private `APPLE_APP_ID=6815838235`; a mismatch fails closed. This replaces the temporary personal-team pending state. Google verification, Android package, price/duration policy, free web access and role permissions remain unchanged. Signed Apple product/purchase/Restore QA remains open under the owner cloud hold. See [ADR](../decisions/ADR-20260929-zeroes-organization-ios-release-identity.md).

Store reviewer access (29 September): a separate persisted `MobileAppReviewGrant` now permits a platform owner to give one synthetic QA-tenant user a time-limited, audited, tenant/environment-bound paid-feature inspection path without a provider purchase. The same signed-mobile snapshot/gate reads the grant, while an unpaid second account still reaches the paywall. The grant expires within 30 days, can be renewed or revoked with audit evidence, and never changes role/finance permissions, provider purchase events or `TenantSubscription`. The local migration and push succeeded on `127.0.0.1:55434/halaalvest`; 26 focused review/purchase/privacy tests and DB/API TypeScript pass. No Production grant, account or store credential exists; final signed-device and repeat-review QA remain release gates. See [the review-grant ADR](../decisions/ADR-20260929-isolate-mobile-store-review-grants.md).

Native complete-pair offer check (29 September): when a store catalog maps both six-month and annual access, the paywall now withholds both purchase actions if the native Apple/Google product lookup resolves only one valid period or omits a localized price. This closes a gap after the Production API's four-mapping guard: a configured pair could previously degrade into a one-option sale or a blank-price purchase action on a particular device or storefront. Sandbox catalogs with only one mapped period remain usable for incremental testing; Restore and Manage are independent of this new-sale display check. Thirteen focused mobile/API tests, mobile TypeScript, scoped lint and formatting pass. Live product creation, exact selectable Nigerian prices, storefront territories and signed-device purchase/Restore evidence remain open under the owner cloud hold.

Native subscription-management package correction (29 September): personal and historical native Manage actions now pass the active Expo public `android.package` to Play's subscription link rather than hardcoding `com.halaalvest.mobile`. Preview builds resolve `com.halaalvest.mobile.preview`; Production resolves `com.halaalvest.mobile`. If Android package metadata is absent, the action gives the existing manual store-settings guidance instead of opening a link for the wrong package. iOS passes no Android package. Focused helper/restoration tests, mobile TypeScript, Expo config evaluation and lint pass locally; a signed-device Manage/deep-link check remains open under the cloud hold.

Revoked-user snapshot guard (29 September): the per-user access snapshot now selects purchase rows only when the owning user is not soft-deleted. Retained active/renewing store chains can still receive system notification reconciliation, but a direct snapshot query for that deleted user returns `accessAllowed: false` and no current period. This is one relational read, with no extra user lookup. Twenty-five focused billing/auth tests and DB/API TypeScript pass; signed provider/device behavior remains open under the cloud hold.

Post-revocation store reconciliation (29 September): verified Apple/Google system notifications may now update an existing personal purchase chain or a same-user, same-environment linked successor after account access is revoked. Client verification and unlinked new chains remain blocked; QA purge, ownership, ordering and duplicate guards still apply. The audit event marks reconciliation after revocation. This keeps store renewal/cancellation/refund evidence current without restoring login or changing the deletion request. Twenty-seven focused billing/auth tests, both typechecks, scoped lint and formatting pass; signed provider delivery and approved retention remain open. See [the decision](../decisions/ADR-20260929-reconcile-personal-store-notices-after-access-revocation.md).

Store-cancellation fallback (29 September): the pre-entry Mobile app access screen now links to platform-specific official Apple or Google Play cancellation instructions even when the native store connection is not ready. Its native Manage action still uses the store SDK when available; the guide is an independent recovery path for a user preparing account deletion or facing a store outage. It neither cancels a subscription nor changes personal entitlement or catalog prices. Mobile TypeScript, scoped lint/formatting, five adjacent tests and local Android/iOS JS exports pass; device browser navigation and actual store cancellation remain unverified under the owner hold.

Native receipt verification coalescing (28 September): Restore and a purchase listener now share one in-flight verification for the same Apple transaction ID or Google purchase token. One provider check and native finish run per concurrent receipt, while a completed failure can be retried on a later Restore. Receipts without a transaction identifier fail into review instead of sending an empty verification key; a callback from a disposed login cannot surface that review message. Focused concurrency/retry tests, mobile TypeScript, scoped lint and local Android/iOS exports pass; signed-device StoreKit/Play delivery remains open under the cloud hold.

Native Restore overlap correction (28 September): the personal hook now uses the shared busy-release gate while Restore and store-listener verification overlap. Neither completion unlocks another purchase until the other operation ends, including when StoreKit emits an update during Restore. Mobile TypeScript, scoped lint and 23 adjacent tests pass; the signed-device overlap still needs store QA after the cloud hold.

Native callback ordering correction (28 September): a store listener can report verification or cancellation before the `requestPurchase` promise settles, or while the pre-purchase owned-transaction read is pending. The personal purchase flow now lets that listener retain its result, avoids dispatching a second charge after an observed callback, and keeps verification in control of the busy state. A late request result can no longer replace successful access or a cancellation with a waiting/review message. Mobile TypeScript, scoped lint, 23 adjacent recovery/offer tests and local Android/iOS JS exports pass. A signed-device StoreKit/Play race remains unverified under the cloud hold.

Native/server source checkpoint (28 September): the authenticated mobile shell now checks the personal access snapshot before admin/member feature routes, expires cached access at the verified `accessEndsAt`, and keeps personal billing, Restore, Manage, sign-out, legal, account privacy and public support links available before entry. A signed mobile bearer is subject to a server-side tRPC gate even if the caller omits the mobile source header; web cookie/legacy sessions are outside that gate. The new native loader accepts exact Apple six-month/yearly periods and Google `P6M`/`P1Y` base plans, displays store-localized prices, binds purchases to the signed user UUID, verifies with the server, and leaves Play acknowledgment to the server and Apple finishing until after an applied grant. Existing store purchases block another in-app charge; duration changes go through store management and Restore. The shared authenticated Apple/Google notification endpoint now routes personal products to personal entitlement updates, with legacy tenant products kept separate. The old tenant-plan catalog still offers no new products. Member login and portal provisioning no longer depend on the old tenant plan, so the personal paywall remains reachable. Focused source tests and DB/API/mobile TypeScript pass. No signed-device purchase, active store products, refund delivery, staffed reconciliation, cloud build or release acceptance is claimed.

Cross-cooperative account correction (28 September): the paid snapshot now follows the signed user across all their cooperative memberships in the same store environment. The purchase row retains the user's original tenant for audit provenance. A purchase verification from a selected cooperative requires that user's membership there; normal member/admin data authorization stays tenant and role scoped. This prevents a paid user from being locked out on role/workspace switch or asked to buy the same store subscription again. Focused tests cover a second membership, unrelated-tenant denial and an existing provider chain whose recorded tenant differs from the current home tenant; signed-device switching remains unverified.

Production catalog completeness guard (28 September): new personal offers remain empty when the Production sales switch and public-policy gate would otherwise allow them but the configured catalog does not contain both durations on both stores. The parser also requires the two Google base plans to share one subscription product. Restore IDs and server verification remain separate from the new-sale switch, so a partial historical catalog can still be used for recovery. This is source configuration protection, not proof of live products, exact NGN store prices or signed-device purchases.

The source-presence preflight now passes because all five paths exist. It checks file presence only; store sale remains closed by environment/configuration and the owner cloud hold. The broader meaning of free web admin operations versus legacy cooperative plan limits is pending the owner’s answer. Do not remove finance, KYC, role or migration controls by inference.

Earlier persistence/API checkpoint (28 September): the separate per-user tables, catalog, writer and API were added before the native route and notification wiring described above.

The superseded `subscriptions.storeCatalog` now serves no new tenant-tier products in sandbox or Production; it retains only a historical account binding for any old receipt reconciliation. This prevents a mistaken old monthly tenant offer while the native UI is replaced.

Earlier source-presence checkpoint (28 September): the EAS runner named five required personal-access paths and blocked while they were absent. Those paths now exist, but file presence is not a signed build or purchase test.

## Product decision — 28 September 2026

The web dashboard is free. Every mobile user, including member, staff and administrator roles, buys individual Apple/Google app access on their own store account. The owner chose US$0.99 per six months and US$1.99 per year as USD base prices on 7 October 2026. Checkout uses store-returned localized prices. Both durations unlock the same native app feature area. An unpaid or expired user cannot enter that area; sign-in and a pre-entry purchase/Restore/Manage/recovery shell remain available. Web use and cooperative finance balances never depend on a person's mobile store payment.

## Superseded source mismatch — before 28 September correction

Before the personal path was added, mobile `/subscription`, `subscriptions.storeCatalog` and `verifyStorePurchase` offered administrator-managed monthly tenant plans backed by `TenantSubscription`. That path is retained for historical receipt reconciliation but serves no new offers. Personal access now uses separate per-user persistence, API and pre-entry native billing routes with six-month and annual offers. The prior tenant-tier catalog remains superseded and must not be configured for new sales.

## Implementation boundary and current state

1. Implemented in source: separate per-user app-access purchases and provider events retain user ownership, store identity, verified status/period and audit evidence. They do not post to the cooperative ledger or alter `TenantSubscription`; raw Google tokens are not persisted. The earlier isolated database migration and schema push are recorded in the database Brain docs. No schema change is made by this documentation update.
2. Implemented in source: every authenticated role can query the personal catalog/snapshot and verify a purchase without `manage_subscription`. Provider-signed user binding, chain ownership, store environment, selected-tenant membership, evidence ordering and idempotency guard application. Google acknowledgment follows applied persistence. Signed-provider redelivery and wrong-account Restore still require live QA.
3. Implemented in source: native six-month and annual offers use store-localized prices, with pre-entry purchase, Restore, Manage and cancellation guidance. The app blocks a second charge when an owned purchase exists. Store-side duration changes, callback ordering and overlapping Restore remain unverified on signed devices.
4. Implemented in source: mobile feature routes and ordinary signed-mobile API calls require current personal access. Billing, legal, support, account privacy, sign-out and purchase recovery stay reachable before entry. Web sessions do not require a personal mobile purchase. Live role/tenant/device checks remain open.
5. Still open: verify the intended scope of free web administrator operations against any legacy cooperative plan limits. Preserve finance authorization, KYC and migration controls while resolving it; do not treat Free Beta as a personal app purchase.
6. Still open for release: provider products and exact selectable NGN prices, Apple/Google account readiness, signed-device purchase/Restore/renewal/expiry/refund QA, public legal approval, staffed reconciliation and the owner's cloud hold. No cloud build, deployment, OTA or submission is authorised under that hold.
