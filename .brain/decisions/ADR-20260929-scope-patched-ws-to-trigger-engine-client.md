# ADR: Scope patched ws to Trigger's Engine.IO client

Date: 29 September 2026
Status: Accepted for local source after integration checks; accepted Linux/Trigger artifact open

## Context

The exact lock selected `ws@8.17.1` beneath `trigger.dev@4.5.16`/`@trigger.dev/core@4.5.16` → `socket.io-client@4.7.5` → `engine.io-client@6.5.4`. The Engine.IO client declares `ws:~8.17.1`, so its existing copy is below the [tiny-fragment memory exhaustion patch at 8.21.0](https://github.com/advisories/GHSA-96hv-2xvq-fx4p). A [later fragment-guard issue](https://github.com/advisories/GHSA-73jw-fp74-p77x) is patched from 8.21.1; the [8.21.3 upstream release](https://github.com/websockets/ws/releases/tag/8.21.3) is available. Other selected ws major lines and parents must remain untouched.

## Decision

Set the parent-scoped root override `engine.io-client>ws:8.21.3` and select the exact 8.21.3 package under `engine.io-client/ws` in `bun.lock`. This is an explicit cross-minor exception to Engine.IO client's `~8.17.1` range. Bun 1.3.0 preserved the old nested version when the override was added to the existing lock, so the one lock entry was replaced with version and integrity generated by an offline disposable Bun 8.21.3 project. Frozen and normal offline installs preserve the resulting lock; recheck the exact selection whenever Bun, Engine.IO, Socket.IO, Trigger or ws changes. Do not use a global ws override: separate ws 6/7 consumers have distinct compatibility requirements.

## Verification and limits

The lock SHA-256 is `aa8621cf354abe99ee07f6badcbd837b22c7e9fe63e58596c92b6fc7b8183a7d`. Versus v116, the root manifest and lock add only this scoped override, and the lock changes only the `engine.io-client/ws` version/integrity entry. Exact-lock `bun audit --json` moved from **0 critical/7 high/21 moderate/4 low** to **0 critical/6 high/20 moderate/4 low**, removing the high and moderate ws IDs without an added finding. The main checkout's ignored Bun symlink still targeted 8.17.1 after frozen install and was corrected locally; the parent then resolved 8.21.3.

A localhost-only Socket.IO server round-trip used Trigger's selected `socket.io-client@4.7.5`, `engine.io-client@6.5.4` and resolved `ws@8.21.3` with the WebSocket transport. Jobs TypeScript, Trigger CLI `--version` (4.5.16), and a 943-module jobs-task Bun bundle passed. These checks establish the exercised client protocol path, not every Engine.IO option or accepted Trigger/Linux runtime. The future accepted archive must resolve the same ws copy and exercise its own connection path before closing the artifact gate. No cloud build, upload, deploy, OTA, submission or policy publication occurred.
