## Implementation

`UploadEvidenceInput` requests an authenticated upload intent, then uses `@vercel/blob/client` to send bytes directly to a **private** Blob store. The Function never receives a 10 MB request body. A 30-minute HMAC intent binds the server-created UUID/path, tenant, uploader, and one of four allowed purposes, allowing a slow transfer to finish before finalization; the provider upload token lasts five minutes. Token issuance validates that intent against the current active tenant membership and exact pathname, restricts MIME to PDF, GIF/JPEG/PNG/WebP, CSV, or plain text, caps size at 10 MiB, and prohibits overwrite. An intent first creates a tenant/uploader/purpose/MIME/size lifecycle row. Token issuance requires that row to remain pending. Finalization checks that a private Blob exists with the expected pathname, size and MIME, then marks the row uploaded and writes `file.uploaded` audit in one Serializable transaction. Retried finalization returns the existing row without a duplicate audit. The member-document, receipt, opening-balance and support-message save paths claim the upload for one exact business record in the same transaction; purpose, tenant, original uploader, uploaded status and single-claim state are checked. GET requires active tenant membership, the stored purpose/type/record-id claim, and the same saved business record URL in the tenant. Staff can read linked records; members can read only linked evidence owned by their member record or support case. Unlinked objects return 404. GET streams through an authenticated Function with `Cache-Control: private, no-store` and `nosniff`. The direct Blob URL is never returned as the evidence URL. The old filesystem POST remains development-only and production/Vercel returns 503 on it.

`DASHBOARD_PRIVATE_BLOB_ENABLED=1`, a private `BLOB_READ_WRITE_TOKEN`, and a distinct 32+ character `DASHBOARD_UPLOAD_SIGNING_SECRET` are all required to activate the flow. Leave the enable switch at `0` until every gate below passes. Configure these as server secrets, never with `NEXT_PUBLIC_`. Attach only the Preview token to Preview and only the Production token to Production. Both stores were created as **private** in `fra1`; region and access cannot later be changed. Do not use a public Blob store or use the QA tenant's files as Production evidence.
