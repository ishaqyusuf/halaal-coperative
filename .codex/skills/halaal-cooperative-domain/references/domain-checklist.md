# Halaal Cooperative Domain Checklist

Use this reference when a task needs a quick domain QA pass.

## Finance Safety

- Every money amount has an owner, tenant, source event, and explainable calculation.
- Reserves, active commitments, posted balances, staged records, and reversals are not mixed silently.
- Disbursement eligibility is treated as a reviewable decision, not a guarantee.
- Posted financial history is corrected through auditable events, not destructive overwrites.

## Halaal Constraints

- Loans or financing must remain interest-free.
- Fees and charges must be explicit, policy-backed, and not disguised interest.
- Profit allocation should come from actual cooperative investment/business results, not time value of money.
- Any non-compliant income treatment should be visible and reviewable if the model supports it.

## Admin Operations

- The first screen should answer: what is unsafe, overdue, pending, blocked, or ready for approval?
- Normal completed records belong lower than exceptions and decisions.
- Admin actions should link directly to the workspace that resolves the issue.
- Setup diagnostics should be warnings, not primary operating metrics.

## Member Trust

- Members should be able to trace savings, charges, repayments, financing, and profit allocations.
- Statements should distinguish posted records from staged/imported/backfilled records.
- KYC, document review, and approval status should be clear and role-scoped.
