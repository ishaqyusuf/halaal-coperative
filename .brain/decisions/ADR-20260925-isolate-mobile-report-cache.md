# ADR — Isolate and clear native report exports

Status: Accepted in source on 25 September 2026; signed-device file-lifecycle QA remains open.

Member statements and administrator reports contain cooperative financial data. Previously, native CSV exports used a server-provided filename directly in the shared app cache. Screen cleanup removed known files on normal unmount or expiry, but a process exit could leave an export behind, and two generations with the same filename could overwrite each other.

New exports use unique UUID-prefixed filenames inside an app-owned `halaalvest-private-reports` cache directory. The app removes that directory on cold session hydration, sign-in, session invalidation/sign-out and cooperative-role transition. It also scans the root app cache and removes only filenames matching the two former export shapes (`<tenant>-<report-key>-report.csv` for a known report key or `<tenant>-<member-number>-statement.csv`), leaving unrelated cache entries alone. Both report controllers invalidate in-flight generation when the session token, access state or mounted screen changes, so a late response cannot recreate an export for a departed context. Normal cancel, expiry and unmount cleanup remains. The operating system or a share recipient can retain copies outside this directory; this mechanism is local cache hygiene, not server-side account erasure or a promise to revoke a shared file.

The legacy cleanup recognizes the filename shapes generated by the current server export endpoints, but cannot prove that every prior binary used those shapes. Inspect upgrade and file lifecycle on a signed device before treating local export residue as fully closed.
