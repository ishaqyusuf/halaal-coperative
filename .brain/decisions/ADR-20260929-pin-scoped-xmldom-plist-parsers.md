# ADR: Patch both plist XML parser lines without collapsing majors

Date: 29 September 2026
Status: Accepted for source; clean release install and signed-artifact verification open

## Context

The lock selected `@xmldom/xmldom@0.8.13` for `@expo/plist@0.4.9` (`^0.8.8`) and `0.9.10` for `plist@3.1.1` (`^0.9.10`, reached through `simple-plist`/Xcode tooling). The [upstream 0.8.15 release](https://github.com/xmldom/xmldom/releases/tag/0.8.15) and [0.9.12 release](https://github.com/xmldom/xmldom/releases/tag/0.9.12) patch the current parser advisories on their respective maintained lines. A global one-version override would cross one parent's declared minor-zero series; the current mobile source has no first-party direct plist or xmldom import.

## Decision

Use parent-scoped root Bun overrides: `@expo/plist>@xmldom/xmldom:0.8.15` and `plist>@xmldom/xmldom:0.9.12`. Both stay within the parents' declared ranges and leave other dependency majors untouched. Bun 1.3.0 resolved both correctly in a clean disposable two-parent project, but `bun install` and `--force --lockfile-only` retained the old versions in the existing monorepo lock. `bun update @xmldom/xmldom` instead added an unintended direct root dependency; that attempt was fully reverted. The final two lock entries were replaced narrowly with the exact version/integrity entries generated by the clean Bun probe. A normal lockfile-only install in a separate copy preserved the resulting lock byte for byte; frozen install passes. Review this targeted lock procedure when changing package-manager versions.

## Verification and limits

The lock SHA-256 is `f4e656be5696d49222fd9f750d7182250c11f02f47b43701839a6f510393b6fc`, still lockfile version 1. Relative to the preceding tar-override lock, only the two scoped overrides and two corresponding package versions/integrities changed; no workspace section or other package entry changed. The exact-lock audit moved from **0 critical/46 high/51 moderate** to **0 critical/27 high/47 moderate**. All 23 xmldom advisories disappeared, with no added finding. Three ignored Bun links were corrected locally so the installed Expo and plist parents resolve 0.8.15 and 0.9.12.

Both installed plist APIs round-tripped a representative nested app-property document. `@expo/plist` returns null-prototype parsed dictionaries by its own existing `parse.js`; the value comparison passed after normalizing that prototype. Mobile TypeScript, the focused Expo-config test, and local production-variant Expo prebuild-config evaluation pass. A local iOS JS export with unreachable `.invalid` service origins bundled 3,140 modules; its source map contains no xmldom/plist module. These checks verify source/config and local parser behavior, not the clean EAS install, native prebuild, signed app or untrusted XML processing in every third-party caller. The owner cloud hold, remaining highs and draft-policy gates remain.
