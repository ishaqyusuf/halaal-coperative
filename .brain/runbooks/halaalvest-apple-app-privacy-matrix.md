# Apple App Privacy evidence matrix

Draft for the current HalaalVest iOS `1.0.0` store-source target, updated 25 September 2026. The generated native/privacy evidence below predates that version change and is not a signed `1.0.0` IPA. **No App Store Connect privacy answers are approved or published by this packet.** The iOS IPA, final runtime configuration, third-party SDK report, processor terms and live privacy page are not yet available. Reconcile every candidate with that final build before entering answers. This packet covers data sent from the iOS app and retained by HalaalVest or integrated partners; the [Play matrix](halaalvest-play-data-safety-matrix.md) separately covers Android.

[Apple's App Privacy guidance](https://developer.apple.com/app-store/app-privacy-details/) requires data types collected by the app **or integrated third-party partners**, including data used only for app functionality. Collection means off-device transmission that remains accessible beyond the real-time request. Apple asks for each type's purpose, whether it is linked to the user and whether it is used for tracking. Optional disclosure has a narrow all-conditions test; merely having an optional screen or a user-initiated action is not enough. [App Store Connect](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy) requires a public iOS privacy-policy URL and app-level answers across all distributed platforms. These are Apple rules, not conclusions that any owner-approved disclosure already exists.

## Cross-cutting decisions before App Store Connect entry

- **Linkage:** Name, contact, member finance, support, purchase and account identifiers are tied to users or devices in current source. Do not label them “Data Not Linked to You” merely because an analytics identifier is pseudonymous. Apple requires de-identification before collection and no later relinking for that label. [Apple linkage definition](https://developer.apple.com/app-store/app-privacy-details/#data-linked-to-you).
- **Tracking:** No targeted-advertising or data-broker path was identified in application source. This is **not** a final “Data Used to Track You: No” answer: obtain the final IPA SDK/privacy report and vendor data-use terms. Apple's tracking definition includes an integrated SDK that repurposes app data for cross-company ad targeting even if HalaalVest does not request that behavior. [Apple tracking definition](https://developer.apple.com/app-store/app-privacy-details/#tracking).
- **Privacy manifest:** The old untracked development iOS tree had an empty `NSPrivacyCollectedDataTypes` array; it never proved no collection. `apps/mobile/app.config.ts` now declares an app-owned baseline for Name, Email Address, Phone Number, Physical Address, User ID, Device ID, Other Financial Info, Purchase History, Customer Support and Other User Content. Each is marked linked to the user for App Functionality, with app-owned tracking false. A disposable **production** Expo prebuild before the `1.0.0` source-version change on 25 September generated `ios/Halaalvest/PrivacyInfo.xcprivacy` with all ten unique entries, passed `plutil -lint`, and included the manifest in the Xcode target's Resources. The disposable source copy used the then-current app config and release-env guard with the installed main-checkout dependencies; it was not a full current-source IPA build. CocoaPods then installed 120 pods and aggregated four required-reason API categories into that app manifest: FileTimestamp (`C617.1`, `0A2A.1`, `3B52.1`), UserDefaults (`CA92.1`), DiskSpace (`E174.1`, `85F4.1`) and SystemBootTime (`35F9.1`). The Pods project references 11 privacy-manifest resources. Its Sentry manifest separately declares Crash Data, Performance Data and Other Diagnostic Data as unlinked, for App Functionality; no parsed Pod manifest declares tracking true. These are generated-project/package declarations, **not** a signed IPA, a merged Xcode privacy report or proof of Sentry's actual runtime payload/linkage. Conditional search, diagnostics, photos/documents, SDK identifiers, processor use and tracking classifications above remain unresolved; reconcile the final archive and network traces before App Store Connect answers. [Apple manifest guidance](https://developer.apple.com/documentation/bundleresources/describing-data-use-in-privacy-manifests), [Expo configuration](https://docs.expo.dev/guides/apple-privacy/).
- **Privacy links and deletion:** The required public `https://halaalvest.com/privacy` route and optional privacy-choices route must resolve without Vercel authentication and match effective, approved text before listing entry. The current Production routes returned 404 on 25 September. The deletion flow records verified requests and staged access revocation locally, but approved erasure/retention, processor outcomes and completion notice are unfinished. Do not claim complete account-data deletion in App Privacy or review notes. See [launch legal readiness](../features/launch-legal-and-store-readiness.md) and [deletion map](account-deletion-data-map.md).
- **Final capture:** Record the exact signed IPA/build, its runtime flags and privacy report; capture each network destination/payload class with a synthetic account; map every data type to purpose, linkage, tracking, first/third-party recipient and retention; obtain owner/legal and processor review; then enter and publish the answers in App Store Connect. Apple says the response is app-level and includes integrated third-party partners. No console answer is ready merely because this draft names a candidate.
